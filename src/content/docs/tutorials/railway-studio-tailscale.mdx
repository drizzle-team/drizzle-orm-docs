This tutorial puts a database browser on your tailnet and never gives it a public domain. The template deploys the browser together with a small [Tailscale](https://tailscale.com/) service that is already wired to it, so there are no port mappings to write.

You do not generate or paste a key. The Tailscale service prints a sign-in link into its deploy log, and you click it.

<Callout type="info">
If you already run Drizzle Studio or Drizzle Gateway on Railway from the plain template, follow [Add Tailscale to Drizzle Studio or Gateway on Railway](/docs/tutorials/railway-tailscale-existing-project) instead. That template adds one Tailscale service to your project and nothing else.
</Callout>

To connect `drizzle-kit` on your machine to the database over your tailnet, follow [Connect Drizzle Kit to a private Railway database with Tailscale](/docs/tutorials/railway-postgres-tailscale).

<Prerequisites title="This guide assumes the following:">
  - You have a [Railway](https://driz.link/railway) account.

  - You are on the Railway Hobby plan or higher. The Free plan allows one volume per project, and this setup needs two for Studio or three for Gateway, counting the database. The Trial plan ends after 30 days and limits outbound network access, which the Tailscale service needs.

  - You have a [Tailscale](https://tailscale.com/) account.

  - You have the Tailscale client installed on the machine you work from, and that machine is signed in to your tailnet. You can find the downloads on the [Tailscale website](https://tailscale.com/download).
</Prerequisites>

## How it works

The template creates two services and neither gets a public domain. The browser is the same image as the plain template. Next to it runs a Tailscale service that joins your tailnet as its own machine and forwards its port to the browser over Railway's private network. Traffic goes from your device over the tailnet to that machine, and from there to the browser.

Railway's private network is still how the browser reaches your database. The database keeps its `*.railway.internal` domain and stays unreachable from anywhere else.

## Set up the Railway project

<Steps>
#### Create a Railway project

Log in to your [Railway dashboard](https://railway.app/dashboard) and click the `New Project` button.

![](@/assets/images/tutorials/railway-create-service-menu.png)

#### Provision a PostgreSQL database

On the project canvas, click the `New` button in the top right corner and select `Database` → `PostgreSQL`. You can also use the command palette (`Cmd/Ctrl + K`) and search for PostgreSQL.

![](@/assets/images/tutorials/railway-select-postgres.png)

#### Keep the database on the private network

Click on the PostgreSQL service, go to the `Settings` tab, and find the `Networking` section. Verify that public access is disabled. Under `Private Networking` you will see the private domain of the service, for example `postgres.railway.internal`.

![](@/assets/images/tutorials/railway-postgres-private-networking.png)

</Steps>

<Callout type="info">
You can also deploy into a project that already has a database. The template adds two services, the browser and a Tailscale service, and nothing else.
</Callout>

## Check your tailnet

<Callout type="info">
Nothing here is required to start. MagicDNS is on by default for every tailnet created since October 2022. HTTPS certificates are optional: with them the address is `https://`, without them it is `http://` on port 4983, and the connection is encrypted by Tailscale either way. If you want the `https://` address, enable **HTTPS Certificates** on the [DNS page](https://login.tailscale.com/admin/dns) at any time; the Tailscale service notices on its own.
</Callout>

## Choose Gateway or Studio

Drizzle has two browsers, and a Tailscale template for each.

<TableWrapper>

| | Drizzle Studio | Drizzle Gateway |
| --- | --- | --- |
| Databases | One, fixed to the `DATABASE_URL` you set in Railway | Many, you add and edit them in the UI |
| Access | `PASSCODE` generated by the template | `MASTERPASS`, plus passcodes you hand out |
| Storage | None | A volume holding saved connections |

</TableWrapper>

Pick **Drizzle Studio** when everyone on your tailnet should reach a single database and nothing else.

<br />

Pick **Drizzle Gateway** when you need to manage several databases, or hand specific people access to specific ones. Keep in mind that a Gateway user who knows `MASTERPASS` can add a connection to any database the service can reach.

#### Sign in from the deploy log

Open the **Tailscale** service, then its `Deployments` tab, and read the deploy log. The last lines of the log hold a sign-in link:

```plaintext
This service is not on your tailnet yet. Open this link and sign in
with the account that owns your tailnet:
  https://login.tailscale.com/a/xxxxxxxxxxxx
```

Open the link and sign in. Anyone who opens that link first gets this machine on their tailnet, so do not forward it. The log is visible only to members of your Railway project.

If your tailnet requires device approval, the log says so and the machine waits until you approve it on the [Machines page](https://login.tailscale.com/admin/machines).

#### Read the address from the deploy log

A few seconds after you sign in, the same log prints where to go:

```plaintext
joined tailnet: example.com
4983: ready
open https://drizzle-studio.example-com.ts.net from any device on your tailnet
```

Check that the tailnet name is yours. If it is not, remove the machine from the Machines page and redeploy the Tailscale service.

The machine name can end in `-1`, `-2` and so on if your tailnet already has a machine with that name. Use the address the log prints.

If HTTPS certificates are off in your tailnet, the address starts with `http://` and ends in `:4983` instead. That address works in the same way.

If you set `TS_FORWARD_DATABASE`, the log also prints `5432: ready`.

#### Open it

Open that address in your browser. Drizzle Studio asks for a passcode on first use.

Go back to the service in Railway, open the `Variables` tab, and copy the value of `PASSCODE`. Paste it into the prompt.

#### Check the connection

Drizzle Studio opens on the database from `DATABASE_URL`, so there is nothing to connect by hand.

## Use other ports

By default, `TS_FORWARD_BROWSER` uses port 4983 and `TS_FORWARD_DATABASE` uses port 5432, on the machine and on the service. To use other ports, write the value in the form `[port:]host[:port]`:

<TableWrapper>

| Value | Port on the machine | Port on the service |
| --- | --- | --- |
| `host` | The default port | The default port |
| `host:port` | `port` | `port` |
| `source_port:host:target_port` | `source_port` | `target_port` |

</TableWrapper>

For example, `5433:${{Postgres.RAILWAY_PRIVATE_DOMAIN}}:5432` forwards port 5433 on the machine to port 5432 of the database service.

If the port on the machine for `TS_FORWARD_BROWSER` is not 4983, an `http://` address in the log ends in that port.

## Keeping it running

A machine that joined by signing in has its key expire on your tailnet's schedule, 180 days by default. When that happens, the Tailscale service prints a new sign-in link and waits. The address stops answering until you click it.

To avoid that, open the [Machines page](https://login.tailscale.com/admin/machines) once, find the machine, open the menu at the far right of its row, and choose `Disable key expiry`.

Railway charges $0.05 per GB of egress, which is traffic that leaves Railway, and traffic over your tailnet leaves Railway. Browsing costs very little. A 20 GB `pg_dump` over port 5432 costs about $1. Check the current price on [Railway pricing](https://railway.com/pricing).

<Callout type="info">
If you automate deployments and want no sign-in at all, set `TS_AUTHKEY` on the Tailscale service to an auth key or an OAuth client secret. With an OAuth secret, also set `TS_TAGS` to a tag you own, for example `tag:drizzle`. A tagged machine never has its key expire.
</Callout>

## Troubleshooting

<Callout collapsed="A new sign-in link appeared in the log">
**A new sign-in link appeared in the log.** The service restarted, for example after the key expired or the machine was removed. Open the newest link. The link works once.
</Callout>

<Callout collapsed="The log says the machine is waiting for approval">
**The log says the machine is waiting for approval.** Your tailnet has device approval turned on. Open the [Machines page](https://login.tailscale.com/admin/machines) and approve it. No redeploy is needed.
</Callout>

<Callout collapsed="Studio opens but shows no tables">
**Studio opens but shows no tables.** `DATABASE_URL` points at a service outside this project, or you pasted a connection string by hand and it does not match your database. Open the Drizzle Studio service, go to `Variables`, set `DATABASE_URL` to `${{<your database service>.DATABASE_URL}}`, and click `Deploy`.
</Callout>

<Callout collapsed="The address does not open">
**The address does not open.** Run `tailscale status` on your device and check it is signed in to the same tailnet the log named. If the log printed an `http://` address, use that exact form with the port; there is no `https://` until HTTPS certificates are on in your tailnet.
</Callout>

<Callout collapsed="It worked for months and then stopped">
**It worked for months and then stopped.** The machine's key expired. Open the Tailscale service's deploy log; it is printing a fresh sign-in link. Click it, then disable key expiry on the machine so it does not happen again.
</Callout>

<Callout collapsed="The machine name gained a -1 suffix">
**The machine name gained a `-1` suffix.** Your tailnet already had a machine with this name, for example from an earlier deploy. Tailscale keeps the suffix. Rename the machine on the Machines page if you want the short name. Otherwise, use the address the log prints.
</Callout>

<Callout collapsed="The log prints no open line">
**The log prints no `open` line.** `TS_FORWARD_BROWSER` is empty, or the Tailscale service skipped it. A reference resolves to an empty value when it names a service that was not in the project when the template deployed. A skipped variable has its own line in the log, and the next entry explains that line. Open the Tailscale service's `Variables` tab, set `TS_FORWARD_BROWSER` to `${{"Drizzle Gateway".RAILWAY_PRIVATE_DOMAIN}}` (with `"Drizzle Studio"` for Studio), and click `Deploy` in the top bar.
</Callout>

<Callout collapsed="The log prints a line that ends in skipped">
**The log prints a line that ends in `skipped`.** The line starts with the variable name, then gives the reason:

- `does not match [port:]host[:port]`: the value has more than two colons.
- `has an empty target host`: the value has a port but no host. A reference that names a service outside your project resolves to an empty host.
- `still contains a Railway reference that did not resolve`: Railway did not replace the reference. Check the service name inside it.
- `has a port outside 1-65535`: a port is not a number from 1 to 65535.
- `reuses port`: an earlier forward already uses that port on the machine.

Fix the value on the Tailscale service's `Variables` tab and click `Deploy` in the top bar.
</Callout>
