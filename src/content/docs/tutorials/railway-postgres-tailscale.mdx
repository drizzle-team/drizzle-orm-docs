This tutorial connects `drizzle-kit` on your device to a PostgreSQL database on [Railway](https://driz.link/railway) that has public access turned off.

You add a small [Tailscale](https://tailscale.com/) service to the project that holds the database. It joins your tailnet as its own machine and forwards the database port to that machine. Every device on your tailnet can then run migrations against the database.

You do not generate or paste a key. The Tailscale service prints a sign-in link into its deploy log, and you click it.

<Callout type="info">
If you also want a database browser on your tailnet, start with [Drizzle Studio and Gateway on Railway with Tailscale](/docs/tutorials/railway-studio-tailscale). Its templates come with the same Tailscale service.
</Callout>

<Prerequisites title="This guide assumes the following:">
  - You have a [Railway](https://driz.link/railway) account.

  - You are on the Railway Hobby plan or higher. The Free plan allows one volume per project. Your database needs one volume, and the Tailscale service needs another. The Trial plan ends after 30 days and limits outbound network access, which the Tailscale service needs.

  - You have a [Tailscale](https://tailscale.com/) account.

  - You have the Tailscale client installed on the device you work from, and that device is signed in to your tailnet. You can find the downloads on the [Tailscale website](https://tailscale.com/download).

  - You have installed Drizzle ORM and [Drizzle Kit](/docs/kit-overview).
  <Npm>
      drizzle-orm@rc
      -D drizzle-kit@rc
  </Npm>
</Prerequisites>

## How it works

Railway gives every service a private domain that ends in `.railway.internal`. Those domains resolve only inside the project, so `drizzle-kit` on your device cannot use them.

The Tailscale service solves that from both sides. It runs in the same Railway project, so it resolves the private domains. It also joins your tailnet as a machine, so your own devices reach it by its machine name. Traffic goes from `drizzle-kit` over the tailnet to that machine, and from there to the database over Railway's private network.

## Set up the Railway project

<Steps>
#### Create a Railway project

Log in to your [Railway dashboard](https://railway.app/dashboard) and click the `New Project` button.

![](@/assets/images/tutorials/railway-create-service-menu.png)

#### Provision a PostgreSQL database

On the project canvas, click the `New` button in the top right corner and select `Database` → `PostgreSQL`. You can also use the command palette (`Cmd/Ctrl + K`) and search for PostgreSQL.

![](@/assets/images/tutorials/railway-select-postgres.png)

#### Keep the database on the private network

Click on the PostgreSQL service, go to the `Settings` tab, and find the `Networking` section. Verify that public access is disabled. Under `Private Networking` you will see the private domain of the service, for example `postgres.railway.internal`.

![](@/assets/images/tutorials/railway-postgres-private-networking.png)

</Steps>

<Callout type="info">
You can also use a project that already has a database. The template adds one Tailscale service and nothing else.
</Callout>

## Check your tailnet

<Callout type="info">
The machine name resolves only when MagicDNS is on. Tailnets created on or after 2022-10-20 have it on by default. If your tailnet is older, check the [DNS page](https://login.tailscale.com/admin/dns).
</Callout>

## Add the Tailscale service

<Callout type="info">
If your project already runs Drizzle Studio with Tailscale or Drizzle Gateway with Tailscale, it already has a Tailscale service, and you can skip this section. Open that Tailscale service, go to the `Variables` tab, and set `TS_FORWARD_DATABASE`: type `${{` and pick `RAILWAY_PRIVATE_DOMAIN` of your database service. Click `Deploy` in the top bar and wait for `5432: ready` in the new deploy log. The machine name is the first part of the address in the `open` line, for example `drizzle-studio`.
</Callout>

<Steps>
#### Deploy the template into the same project

Press the button below to open the Tailscale for Drizzle template.

**Don't deploy it right away** - read this step to the end and set the variables first.

<a
  href="https://railway.com/new/template/tailscale-for-drizzle?referralCode=eobqmj&utm_medium=integration&utm_source=button&utm_campaign=tailscale-for-drizzle"
  target="_blank"
  rel="nofollow noreferrer"
  style="display: inline-block; margin: 16px 0;"
>
  <img src="https://railway.com/button.svg" alt="Deploy on Railway" width="183" height="40" />
</a>

Open the `Deploy to` dropdown and select the project that holds your database. Both services must be in the same project, otherwise the Tailscale service cannot reach the database over the private network.

![](@/assets/images/tutorials/railway-tailscale-database-template-form.png)

#### Set the variables

<TableWrapper>

| Variable | What to set |
| --- | --- |
| `TS_FORWARD_BROWSER` | Leave it empty |
| `TS_FORWARD_DATABASE` | The field is empty. Type `${{`, pick your database service from the list, then pick `RAILWAY_PRIVATE_DOMAIN`. For a service named `Postgres` the field then reads `${{Postgres.RAILWAY_PRIVATE_DOMAIN}}`. |
| `TS_HOSTNAME` | Change it to `railway-postgres`, or pick another name for the machine. You connect to the database by this name. |

</TableWrapper>

Some variables, such as `TS_HOSTNAME`, are in the collapsed `Pre-Configured Environment Variables` section of the card. Expand it to see or change them.

On the service card, click `Save Config`. Then click `Review and deploy`. Railway opens your project with the template in a side panel. Click `Deploy Template` there.

#### Sign in from the deploy log

Open the **Tailscale** service, then its `Deployments` tab, and read the deploy log. The last lines of the log hold a sign-in link:

```plaintext
This service is not on your tailnet yet. Open this link and sign in
with the account that owns your tailnet:
  https://login.tailscale.com/a/xxxxxxxxxxxx
```

Open the link and sign in. Anyone who opens that link first gets this machine on their tailnet, so do not forward it. The log is visible only to members of your Railway project.

![](@/assets/images/tutorials/railway-tailscale-signin-log.png)

If your tailnet requires device approval, the log says so and the machine waits until you approve it on the [Machines page](https://login.tailscale.com/admin/machines).

#### Check the forwarding rule

A few seconds after you sign in, the same log prints:

```plaintext
joined tailnet: example.com
5432: ready
```

![](@/assets/images/tutorials/railway-tailscale-database-log.png)

Check that the tailnet name is yours. If it is not, someone else opened the sign-in link first, and their tailnet can now reach this service. On the project canvas, click the volume under the Tailscale service, open its `Settings` tab, and click `Wipe volume`. Type the confirmation text and click `Wipe`. Railway deletes the machine's key and redeploys the service. The new deploy log prints a new sign-in link. Open that link yourself. Then change the database user's password.

This Tailscale service forwards only the database, so the log prints no address to open.

#### Find the machine name

Open the [Machines page](https://login.tailscale.com/admin/machines). The new machine has the name you set in `TS_HOSTNAME`. If your tailnet already had a machine with that name, the new name ends in `-1`, `-2` and so on. Use the name that the Machines page shows.

</Steps>

## Connect Drizzle Kit from your device

<Callout type="warning">
The device you run `drizzle-kit` on must be signed in to the same tailnet as the Tailscale service, because the database connection goes through the Tailscale service.
</Callout>

<Steps>
#### Set the connection string

Open the PostgreSQL service in Railway, go to the `Variables` tab, and copy `DATABASE_URL`.

![](@/assets/images/tutorials/railway-postgres-database-url.png)

Replace the `***.railway.internal` host with the machine name and keep the rest of the string. `railway.internal` cannot be resolved outside Railway, so you connect through the tailnet instead. Put the result in a `.env` file.

```plaintext copy
DATABASE_URL=postgresql://postgres:password@<machine name>:5432/railway
```

<Callout type="info">
Tailscale encrypts the connection between your device and the Tailscale service, and Railway encrypts the hop between the Tailscale service and the database. Railway's PostgreSQL also accepts TLS through the Tailscale service, so most clients connect with their default settings.
</Callout>

#### Set up the Drizzle config file

Create a `drizzle.config.ts` file in the root of your project:

```typescript copy filename="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/schema.ts",
  out: "./migrations",
  dialect: "postgresql",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

#### Apply your schema

Generate migrations and apply them:

```bash copy
npx drizzle-kit generate
```

```bash copy
npx drizzle-kit migrate
```

For rapid prototyping you can push the schema directly with [drizzle-kit push](/docs/kit-overview#prototyping-with-db-push). For production deployments, prefer the `generate` and `migrate` workflow, so you keep a versioned history of schema changes. See the [Drizzle migrations fundamentals](/docs/migrations) page for details.

#### Check the result

Open the database in [Drizzle Studio](/docs/drizzle-kit-studio):

```bash copy
npx drizzle-kit studio
```

It runs on your device and reads the same `DATABASE_URL`, so it reaches the database through the Tailscale service. Your new tables are there.

![](@/assets/images/tutorials/drizzle-studio-posts-table.png)

</Steps>

<Callout type="info">
For occasional access you do not need Tailscale at all. The Railway CLI opens a temporary tunnel to a private database with `railway connect Postgres --tunnel-only`. The Tailscale service is the right tool when you need a permanent route, or access from every device on your tailnet.
</Callout>

## Use other ports

By default, `TS_FORWARD_DATABASE` uses port 5432, on the machine and on the database service. To use other ports, write the value in the form `[port:]host[:port]`:

<TableWrapper>

| Value | Port on the machine | Port on the service |
| --- | --- | --- |
| `host` | The default port | The default port |
| `host:port` | `port` | `port` |
| `source_port:host:target_port` | `source_port` | `target_port` |

</TableWrapper>

For example, `5433:${{Postgres.RAILWAY_PRIVATE_DOMAIN}}:5432` forwards port 5433 on the machine to port 5432 of the database service. Your connection string then uses port 5433.

## Keeping it running

A machine that joined by signing in has its key expire on your tailnet's schedule, 180 days by default. When that happens, the Tailscale service prints a new sign-in link and waits. The machine stops answering until you click it.

To avoid that, open the [Machines page](https://login.tailscale.com/admin/machines) once, find the machine, open the menu at the far right of its row, and choose `Disable key expiry`.

![](@/assets/images/tutorials/tailscale-machines-disable-key-expiry.png)

Railway charges $0.05 per GB of egress, which is traffic that leaves Railway, and traffic over your tailnet leaves Railway. Browsing costs very little. A 20 GB `pg_dump` over port 5432 costs about $1. Check the current price on [Railway pricing](https://railway.com/pricing).

<Callout type="info">
If you automate deployments and want no sign-in at all, set `TS_AUTHKEY` on the Tailscale service to an auth key or an OAuth client secret. With an OAuth secret, also set `TS_TAGS` to a tag you own, for example `tag:drizzle`. A tagged machine never has its key expire. The Tailscale service reads `TS_AUTHKEY` only before the machine joins. If the machine has already joined, the key has no effect until you remove the machine and wipe the volume. If you use an OAuth client secret, append `?ephemeral=false&preauthorized=true` to the value. Without that suffix, Tailscale removes the machine from the tailnet when it disconnects, and the machine waits for approval before it joins.
</Callout>

## Troubleshooting

<Callout collapsed="drizzle-kit cannot connect">
**`drizzle-kit` cannot connect.** Run `tailscale status` on your device and check that it is signed in to the same tailnet the log named. Then open the Tailscale service's deploy log and look for `5432: ready`. If a line starts with `5432:` and shows an error, the variable is correct, and the database does not answer on its private domain. Check that the database service is running and listens on port 5432. If no line starts with `5432:` and no line starts with `TS_FORWARD_DATABASE`, the variable is empty, or its reference names a service outside your project. Set it on the Tailscale service's `Variables` tab and click `Deploy` in the top bar. If a line starts with `TS_FORWARD_DATABASE`, the next entry explains it. If the machine name does not resolve, open the [DNS page](https://login.tailscale.com/admin/dns) and check that MagicDNS is on. If it is on, open the machine on the Machines page and use its `Full domain` value as the host. `connection refused` that never clears means the database has public networking on and private off, or a different port. Railway's PostgreSQL accepts TLS through the Tailscale service, so you do not need to disable SSL.
</Callout>

<Callout collapsed="The log prints a line that ends in skipped">
**The log prints a line that ends in `skipped`.** The line starts with the variable name, then gives the reason:

- `does not match [port:]host[:port]`: the value has more than two colons.
- `has an empty target host`: the value has a port but no host. A reference that names a service outside your project resolves to an empty host.
- `still contains a Railway reference that did not resolve`: Railway did not replace the reference. Check the service name inside it.
- `has a port outside 1-65535`: a port is not a number from 1 to 65535.
- `reuses port`: an earlier forward already uses that port on the machine.
- `uses port 443, which the https listener owns`: pick another port on the machine. The browser address already uses 443 when HTTPS certificates are on.

Fix the value on the Tailscale service's `Variables` tab and click `Deploy` in the top bar.
</Callout>

<Callout collapsed="A new sign-in link appeared in the log">
**A new sign-in link appeared in the log.** The service restarted, for example after the key expired or the machine was removed. Open the newest link. The link works once.
</Callout>

<Callout collapsed="The log says the machine is waiting for approval">
**The log says the machine is waiting for approval.** Your tailnet has device approval turned on. Open the [Machines page](https://login.tailscale.com/admin/machines) and approve it. No redeploy is needed.
</Callout>

<Callout collapsed="It worked for months and then stopped">
**It worked for months and then stopped.** The machine's key expired. Open the Tailscale service's deploy log; it is printing a fresh sign-in link. Click it, then disable key expiry on the machine so it does not happen again.
</Callout>

<Callout collapsed="The machine name gained a -1 suffix">
**The machine name gained a `-1` suffix.** Your tailnet already had a machine with this name, for example from an earlier deploy. Tailscale keeps the suffix. Rename the machine on the Machines page if you want the short name. Otherwise, use the name that the Machines page shows.
</Callout>
