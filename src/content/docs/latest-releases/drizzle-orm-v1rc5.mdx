## Drizzle ORM

### Breaking changes

- Fixed `postgres-js` transparent parsers set by `drizzle()` constructors breaking driver's own serializers for `timestamptz`, `timestamp`, `date`, `time`, `json`, `jsonb` types (fixes [#3171](https://github.com/drizzle-team/drizzle-orm/issues/3171), [#4426](https://github.com/drizzle-team/drizzle-orm/issues/4426), [#5789](https://github.com/drizzle-team/drizzle-orm/issues/5789))
 **Note:** Any existing workarounds with manual `JSON.stringify(jsonValue)` in raw sql or raw driver calls must be removed to prevent double stringification of JSON params; For array-type JSON params in `sql` use `sql.param(jsonArrayValue)` to avoid it being parsed as value list instead of param.
- Restricted `undefined` value passed to fields in relational queries' `where` - now throws an error upon encountering `undefined` in filters, added `EmptyFilter` symbol (`import { EmptyFilter } from 'drizzle-orm/relations'`) that can be used as an explicit replacement of `undefined` where possibly absent filter is desired by design rather than possible bug (fixes [#5636](https://github.com/drizzle-team/drizzle-orm/issues/5636))
  Example:
  ```typescript
    db.query.users.findMany({ where: { isActive: params.isActive ?? EmptyFilter } })
  ```
- Relation filters without conditions (`{}`, or containing only empty conditions) are now skipped like any other empty filter instead of generating `exists (...)` check of relation's presence - use `true` to filter by relation's presence, `false` - by its absence
  Example:
  ```typescript
    // Previously: `where exists (select * from "posts" ...)`, now: no filter
    db.query.users.findMany({ where: { posts: {} } })
    // Users with at least one post
    db.query.users.findMany({ where: { posts: true } })
  ```
- Updated `postgres` codecs: now generic codecs contain only in-json codecs (mirroring `mysql`), contents of drivers' codecs remain unchanged
- Switched `pg` `bytea` in-json codecs from `encode(..., 'base64')` casts to decoding `to_json`'s native hex output
- Made nested select join nullification consider `SQL` field data during nullification
- Fixed `sqlite` ignoring `.$defaultFn(...)` on insert when `.default(...)` is present
- Untied `bun-sql/mysql`, `mysql2`, `singlestore` column mapping from connection config, removed forced `bigint` params on their respective configs, replaced with more stable `cast` codecs
- Reworked `cockroach` column builders to mirror `pg` - now both have same `.array('[][]...')` syntax
- Moved `View` exports from `drizzle-orm/sql/sql` to `drizzle-orm/view`
- `getTableUniqueName` no longer prefixes aliased views or tables with their `schema`
- `getTableUniqueName` no longer sets `public.` prefix for entities without `schema`
- Updated `View` class: switched to `Table`-like object config for type template, typed `schema` property
- Updated `withReplicas` (indirectly fixes [#4185](https://github.com/drizzle-team/drizzle-orm/issues/4185)):
  - Now every query goes to primary db by default
  - To query replica, explicitly call `db.$replica`
- Added `withCastCodecs = false` switch to `getSQL()`, `withCastCodecs = true` switch to `toSQL()` of non-relational query builders - now `db.select(...).from(...).getSQL()` emits query without cast codecs by default
- Reworked `sqlite-proxy`:
  - Added `rowMode: 'array' | 'object'` switch for `'all' | 'get'` execute methods
  - Dropped `{ rows: Result[] }` callback result wrapping - now expected direct return of expected data
  - Replaced `callback`, `batchCallback` with `SqliteProxyExecutors` object - must provide `run`, `all`, `get` handlers & optional `batch` handler
  - Dropped `values` execute method due to it being duplicate of array-mode `all`
  - Added `TRunResult` type inference based on return type of `run` executor, updated `SqliteRemoteDatabase` template with `TRunResult` argument
  - Added per-item `rowMode: 'array' | 'object'` to `batch`, `batch` is expected to mirror executors' return types per query
- Fixed the `sqlite-proxy` result type for `get` (`data | undefined` at runtime, previously `data[]` in types) (fixes [#5461](https://github.com/drizzle-team/drizzle-orm/issues/5461), [#3394](https://github.com/drizzle-team/drizzle-orm/issues/3394))
- Fixed `sqlite` `db.get(sql)` return type lacking `| undefined` for queries without returned rows
- Omitted query `params` from `DrizzleQueryError` by default, added `paramsInErrors` option to `drizzle` constructor to enable query `params` in `DrizzleQueryError` (fixes [#5939](https://github.com/drizzle-team/drizzle-orm/issues/5939))
  Example:
  ```typescript
  const db = drizzle({
    connection: 'postgres://...',
    paramsInErrors: true
  })
  ```
- For `mysql`, `postgres`, `cockroach`, `mssql` set RQBv2 to new query build strategy to fix slow query plans (fixes [#5245](https://github.com/drizzle-team/drizzle-orm/issues/5245))
  Can be opted out of per query via `strategy` switch: `db.query.users.findMany({ strategy: 'basic' })`
  When used, may break direct references to relations in raw SQL syntax `where`, `orderBy`:
  ```typescript
  // posts with the most comments first
  db.query.posts.findMany({
	with: { author: true, comments: true },
	orderBy: (t, { sql }) => sql`json_array_length("comments"."r") desc, ${t.id}`, // "comments" becomes unreachable due to query nesting
	limit: 2,
  });

  // posts of verified authors
  db.query.posts.findMany({
	with: { author: true },
	where: { RAW: (t, { sql }) => sql`("author"."r"->>'verified')::boolean` }, // "author" becomes unreachable due to query nesting
  });
  ```
- Moved `StringChunk`, `commonStringChunks` exports from `drizzle-orm/sql/sql` to `drizzle-orm/sql/common-chunks` (still exported from `drizzle-orm/sql`)
- Switched RQBv2 build functions to chunk collection: each accepts optional trailing `collectTo: SQLChunk[]` array to push chunks to and returns chunk arrays instead of `SQL`
  **Note:** Chunk arrays embedded into `sql` directly are rendered as value lists - wrap them in `new SQL(chunks)` to use them as query parts
  - `relationsFilterToSQL(...).sql`: `SQL | undefined` -> `SQLChunk[] | undefined`, added `collectTo` parameter
  - `relationsOrderToSQL(...)`: `SQL | undefined` -> `SQLChunk[] | undefined`, added `collectTo` parameter
  - `relationsOrderEntriesToSQL(...)`: replaced `parts: SQL[]` parameter with `collectTo: SQLChunk[]`, `start?: number`; `RelationsOrderSource`'s `from`, `filters` are now `SQLChunk[]`, `SQLChunk[][]`
  - `relationExtrasToSQL(...).sql`: `SQL | undefined` -> `SQLChunk[] | undefined`, added `collectTo` parameter
  - `relationToSQL(...)`: `{ filter?: SQL; joinCondition?: SQL }` -> `{ filter: SQLChunk[]; joinCondition?: SQLChunk[] }`, added `filterTo`, `joinConditionTo` parameters
  - `getTableAsAliasSQL(...)`: `SQL` -> `SQLChunk[]`, added `collectTo` parameter
- Relational queries are now cached by caches with `all` strategy (`global: true`), opt out per query via `withCache: false`
- Replaced `DBQueryConfigWithComment` type with `DBQueryConfigRoot` - config of root relational query containing all root-only options (`strategy`, `comment`, `withCache`); dialects' relational query builders accept it with options they don't support omitted

- Fixed [drizzle-kit generate drops column alterations when a column with the same name is renamed in another table](https://github.com/drizzle-team/drizzle-orm/issues/6360)
- Updates in `pull` command - migration.sql is no longer has comments when running `pull --init`
- Fixed [drizzle-kit v1 `generateMigration` cannot resolve create/delete ambiguity programmatically (no `HintsHandler`)](https://github.com/drizzle-team/drizzle-orm/issues/6053). `generateMigration` and `pushSchema` from `drizzle-kit/payload/*` and `drizzle-kit/api-postgres` accept `{ hints }` as the last argument: an array of the hint objects that the CLI `--hints` flag takes. If a rename question or a data loss confirmation has no hint, they throw an error with `code: 'missing_hints'` and the list of entities in `missingHints`. Entity ids use `public` as the schema for SQLite and MySQL and `dbo` as the default schema for MSSQL
- Fixed `generateMigration` from `drizzle-kit/payload/sqlite` and `drizzle-kit/payload/mysql` changing the snapshots that it gets when an indexed column is renamed
- Fixed SQLite introspection failing with `chalk is not defined` when a foreign key references a table that has no primary key and the foreign key names no column
- Fixed `drizzle-kit push` failing with a database error when a renamed table, a table moved to another schema or a table in a renamed schema also needed a data loss check
- Updated the data loss warnings of `drizzle-kit push`: all dialects use the same texts and quote every name as in SQL. A warning shows the table by the name that the database has before the push, and adds `(would become ...)` when the push renames or moves the table
- `drizzle-kit push` asks to confirm a dropped column only when the column has a non-null value. Before, PostgreSQL, CockroachDB, MySQL, SingleStore and SQLite asked when the table had a row
- Fixed `drizzle-kit pull` writing SQL text with a backslash, a backtick or `${` into the schema file without escaping it. The pulled schema now compiles and keeps this text in these places. PostgreSQL and CockroachDB: check constraints, views, generated columns, policies, index expressions, index predicates, and default expressions that `pull` writes as a `sql` template. CockroachDB: enum values. MSSQL: check constraints, views, generated columns, index predicates, and default expressions that `pull` writes as a `sql` template. SQLite: generated columns, and default expressions of integer and text columns. For MySQL the pulled schema now compiles when a check constraint, or a default expression that `pull` writes as a `sql` template, has a backtick or `${`. MySQL returns a backslash in this text already escaped, so `pull` writes it unchanged
- The `postgresql` dialect rejects `--ignore-conflicts` in `generate`, `check` and `migrate`. `drizzle-kit generate --fix-conflicts` replaces it
- The bundled agent skills are one skill named `drizzle` now. After `drizzle-kit skills` adds it, the command removes the seven older skills from the project without a question: `drizzle-generate`, `drizzle-push`, `drizzle-pull`, `drizzle-migrations`, `drizzle-hints`, `drizzle-output-modes` and `drizzle-responses-and-errors`
- Fixed `drizzle-orm` not being listed as peer dependency
- Fixed dev dependencies being listed as production
- Fixed [composition of `not` with `or` or `and` causing compile errors](https://github.com/drizzle-team/drizzle-orm/issues/4160).
