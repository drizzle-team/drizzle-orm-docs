# Upgrading to Drizzle v1

<Npm>
 drizzle-orm@rc
 -D drizzle-kit@rc
</Npm>

#### Step 1 - Upgrade the migration files with `drizzle-kit up`

`drizzle-kit up` converts your local migration folder and snapshots to the new format. It does not connect to a database or upgrade its migration history table.

> v3 migration folder discussion: https://github.com/drizzle-team/drizzle-orm/discussions/2832  

We've updated the migrations folder structure by:
- removing `meta/_journal.json`
- grouping SQL files and snapshots into separate migration folders
- removing the `drizzle-kit drop` command

These changes eliminate potential Git conflicts with the journal file and simplify the process of dropping or fixing conflicted migrations

The drizzle-kit has been architecturally redesigned:
- Migrated from database snapshots to DDL snapshots

Commutativity checks were added:
- Detecting non-commutative migrations across branches
> Commutativity discussion: https://github.com/drizzle-team/drizzle-orm/discussions/5005

To migrate from old structure to a new one you would need to run

<Npx>
drizzle-kit up
</Npx>

#### Step 2 - Review breaking changes

You can find out the full list of breaking changes [here](/docs/sqlite/v0-v1-changes#breaking-changes) and make sure to update your code accordingly

If you were using Relational Queries, you need to upgrade to v2:
- [How to migrate relations definition from v1 to v2](/docs/sqlite/relations-v1-v2#how-to-migrate-relations-schema-definition-from-v1-to-v2)
- [How to migrate queries from v1 to v2](/docs/sqlite/relations-v1-v2#how-to-migrate-queries-from-v1-to-v2)

#### Step 3 - Upgrade each database with the v1 migrator

Run `drizzle-kit migrate` for each target database, using the converted migration folder and the existing migration table configuration:

<Npx>
drizzle-kit migrate
</Npx>

The v1 migrator upgrades an existing migration history table if needed, backfills migration names for previously applied migrations, and then applies any pending SQL migrations. This step connects to the target database using its configured credentials.

If you apply migrations through your driver's v1 `migrate()` helper, use that workflow instead. Custom runners that do not call the v1 migrator need to handle the database history upgrade themselves; running `drizzle-kit up` only converts the files.

#### Step 4 - Done ✅
